# Life Simulator

Симулятор деревни на Go с интерактивным интерфейсом в терминале. Жители самостоятельно добывают ресурсы, едят, отдыхают и строят дома. Их решения зависят от потребностей, личных предпочтений и состояния поселения.

Основная идея — наблюдать, как живёт и развивается деревня. При желании можно вмешаться: добавить задания на добычу ресурсов или приостановить строительство.

## Возможности

- **Самостоятельные жители.** Каждый выбирает занятие с учётом голода, усталости и запасов деревни.
- **Предпочтения и навыки.** Жителям нравятся разные занятия, а опыт ускоряет выполнение работы.
- **Общие ресурсы.** Еда и дерево используются для поддержания жизни и строительства.
- **Развитие поселения.** Новые дома увеличивают вместимость деревни, а при наличии жилья и еды могут приходить новые жители.
- **Смена погоды.** Дождь замедляет рубку дерева, но увеличивает сбор еды.
- **Интерактивная консоль.** Можно выбирать жителей, смотреть их характеристики, текущее занятие и прогресс работы.
- **Статистика и журнал событий.** Интерфейс показывает запасы, производство и потребление еды, а также события деревни.
- **Ручные задания.** Работу можно отправлять через интерфейс или локальный HTTP API.
- **Сохранение прогресса.** Деревня и все жители сохраняются в PostgreSQL каждые 30 секунд и при выходе. JSON используется как резервная копия.

Имена жителей загружаются с Random User API в фоне по 100 за запрос; в памяти хранится запас до 200 имён. Рождение и переселение не ждут ответа сайта. Если запас пуст, житель получает постоянное запасное имя «Житель №ID»; получение имён повторяется в фоне.

## Технологии

Go, горутины, каналы и `context` для работы симуляции; `tview` и `tcell` для терминального интерфейса; HTTP API; PostgreSQL и `pgx` для хранения состояния; Goose для миграций; Prometheus и Grafana для мониторинга; Docker Compose для запуска базы и мониторинга.

## Запуск

Все команды выполняются из корня проекта. Нужны Go, работающий Docker и Goose.

```bash
docker compose up -d --wait postgres
```

```bash
export DATABASE_URL='postgres://simulator:simulator_dev@127.0.0.1:5432/life_simulator?sslmode=disable'
```

```bash
goose -dir migrations postgres "$DATABASE_URL" up
```

```bash
go run .
```

Переменная `DATABASE_URL` должна быть задана и при запуске из GoLand. HTTP API доступен по адресу `http://127.0.0.1:8080`; другой адрес можно задать через `HTTP_ADDR`.

## Мониторинг

При работающем симуляторе запусти мониторинг из другого терминала:

```bash
docker compose up -d --wait prometheus grafana
```

Готовый дашборд «Симулятор поселения» доступен по адресу http://127.0.0.1:3000/d/life-simulator. Для просмотра вход не требуется. Локальная учётная запись администратора: `admin`, пароль `simulator_dev`.

Prometheus доступен по адресу http://127.0.0.1:9090, исходные метрики приложения — http://127.0.0.1:8080/metrics. Prometheus собирает показатели каждые 5 секунд и хранит историю 7 дней. Данные Prometheus и Grafana находятся в отдельных Docker volumes и сохраняются при обычном перезапуске контейнеров.

Дашборд показывает население, дома, запасы еды и дерева, рождения, смерти, переселения, доступность симулятора, память Go и количество горутин. История начинается с первого запуска Prometheus. При остановке симулятора показатель доступности становится нулевым, а в графиках его метрик появляются пропуски.

Счётчики `village_births_total`, `village_deaths_total` и `village_immigrants_total` учитывают события с момента запуска процесса и сбрасываются при его перезапуске. Существующие жители из сохранения в эти счётчики не входят. График демографии показывает скорость событий за реальную минуту по формуле `rate(...[1m]) * 60`; это не игровой год. Все три линии положительные, а сбросы счётчиков учитывает Prometheus. Новые метрики появятся после перезапуска обновлённого симулятора, график — после новых сборов Prometheus.

Конфигурация рассчитана на Docker Desktop: симулятор работает на Mac, а Prometheus обращается к нему через `host.docker.internal:8080`. При изменении порта `HTTP_ADDR` поменяй адрес в `monitoring/prometheus/prometheus.yml` и перезапусти Prometheus. Источник данных и дашборд Grafana создаются автоматически из файлов в `monitoring/grafana/`.

Остановить только мониторинг:

```bash
docker compose stop prometheus grafana
```

## Сохранения

Основное сохранение находится в PostgreSQL, идентификатор деревни — `1`. При первом запуске с пустой базой программа переносит существующий `village.json`. Если файла тоже нет, создаётся деревня с тремя жителями. Ошибки чтения существующего сохранения останавливают запуск, чтобы не заменить его новой деревней.

Деревня и полный список жителей, включая умерших, записываются одной транзакцией. При загрузке восстанавливаются ресурсы, возраст, потребности, навыки, суммарная добыча и разрешение строительства. Незавершённые действия сбрасываются, жители заново выбирают занятия; дерево, зарезервированное под незавершённый дом, возвращается в сохранение. Ручная очередь заданий не восстанавливается.

Автосохранение выполняется каждые 30 секунд. Ошибки отображаются в событиях деревни, повторная попытка происходит на следующем интервале. При обычном выходе программа останавливает жителей и выполняет финальное сохранение.

Один и тот же снимок дополнительно записывается в `village.json`, в том числе при ошибке записи в базу. Наличие записи в PostgreSQL имеет приоритет над JSON; резервная копия автоматически импортируется только при отсутствии деревни в базе.

Настройки баланса находятся в `internal/balance/config.json`. Кнопка «Настройки» или F2 позволяет менять их во время работы симуляции.
